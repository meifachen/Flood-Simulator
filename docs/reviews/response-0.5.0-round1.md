# Response to the 0.5.0 review, round 1 (fixed in 0.6.0)

The findings are those of `review-0.5.0-round1.md`. Fail-first was checked against the 0.5.0 code (066baa5): the new engine and coupler checks were run against the pristine snapshot, and each row says what happened there. Checks for brand-new functions are marked as such (they crash or are absent on 0.5.0); doc-only rows have no test. Two items are partial and say so: E-05 (Winter Haven regeneration blocked by the USDA soils service) and E-12 (second-GPU run prepared, not executed — no second GPU exists in the build environment).

## Effect on results

- At the default Courant number the engine is bit-identical (T9's dam break still moves 54,801 / 53,579 / 53,457 / 53,438 cf): F-02 changes only runs below the reference Courant number or with short chunks, which now diffuse less.
- F-01 and F-13 change only runs that previously threw "numerical failure" or overshot in a lake's first chunk; L12/L13 values are unchanged (0.111720 ft; 0.0002/0.0010 ft).
- F-10 changes combination-inlet capture where the curb part carries weir flow (the C10 deep case is unchanged: the orifice side governs under both formulas).
- F-09 changes which cell a flooding node uses only where the old ring pick differed from the nearest cell.
- Everything else is io, docs, tests, or new capability that is off unless used (outlets of the new kinds, on-grade inlets, the D×V threshold recording, provenance).
